[#frontmatter]
== Frontmatter

Frontmatter can be:

- internal, in the file with markup
- external, in the file with the same name and extension `.yaml` or `.yml`

Files are recognized as markup:

- if their extension is associated with a markup language (`.md`, `.adoc`)
- if their extension is `.xml` and their root XML element is associated with a markup language (`TEI`)

[#page-names]
== Page Names
Jekyll relies on page titles being given explicitly in the front matter
and ignores the file names; I had to use a TODO Obsidian plugin to set the
titles from the file names to communicate them to Jekyll;
as a result, pages where the title is different from the file name
(e.g., `index` pages)
had to be marked with TODO in their front matter to disable this plugin
from setting the front matter title.

My plugin uses both the front matter title and the file name for
link resolution, so I can remove this Obsidian plugin and
redundant front matter titles which are the same as the file name,
and set the title in the front matter only when it is different from the file name.

Obsidian uses file names exclusively and ignores the front matter title;
for link resolution to use front matter titles also,

[#chunking]
== Chunking

Previously, I used `asciidoctor-multipage` Asciidoctor
[extension](https://github.com/owenh000/asciidoctor-multipage)
to split an HTML file into per-section pages.

That extension has long-known
[issues](https://github.com/owenh000/asciidoctor-multipage/issues/46),
for example, it does not handle footnotes.

Even if those issues get fixed (which seems extremely unlikely),
this extension only works with AsciiDoc files;
site generator can chunk files in any markup language it supports.

I use the term `chunking` as did DocBook XSLT stylesheets
and not `multi-page` as does AsciiDoctor extension.

Chunking is enabled by setting `chunk` to `true` in the file's front-matter.

Chunking depth is controlled by the `chunk-depth` front-matter field.

[#glossary]
== Glossary

Glossary entries are harvested from a markup-neutral HTML shape
(`class="glossary"` on the list, `class="glossary-item"` with an `id` on each term).
Links to those ids get inline definition tooltips.

AsciiDoc: set `[glossary]` on the description list; term ids come from `[[id]]`.
Reference a term with `<<id>>`.

Markdown: PHP Extra definition lists
(https://michelf.ca/projects/php-markdown/extra/#def-list),
via FlexMark's
https://github.com/vsch/flexmark-java/wiki/Definition-List-Extension[Definition List Extension].
Mark a list with `{:.glossary}` after it
(a Kramdown https://kramdown.gettalong.org/syntax.html#inline-attribute-lists[inline attribute list],
same family of marker as `{:toc}`).
A definition list without that marker is left as FlexMark emitted it:
not a glossary, no term ids, no tooltips.
The marker also separates adjacent lists.

Term id is the `id` on `<dt>` if present, otherwise the term text with spaces turned into hyphens
(`Alter Rebbe` → `Alter-Rebbe`).
Reference a term with `[[#id]]` or `[text](#id)`.

A lone `:` after a Markdown term is not a reliable empty definition:
FlexMark can take the next term as that definition.
Write a real definition line, or omit the term.

[#bibliography]
== Bibliography

Citations become a markup-neutral IR (`span.citation` / `span.citation-item` with `data-key`,
optional `data-locator`, and `data-mode`; `div.bibliography` for the list placeholder).
A per-document BibTeX file plus citeproc-java (CSL) resolve those stubs after footnotes.

Front matter on the document (no site config, no default file or style):

- `bibliography` — path to a `.bib` file, relative to the source file
- `csl` — CSL style name from the bundled Citation Style Language styles (for example `apa`, `ieee`)
- `lang` — CSL locale; falls back to the site `lang`, then `en-US`

Both `bibliography` and `csl` are required to resolve citations.
Only works cited on the page appear in the list.
Resolved in-text cites become `a.citation` links to `#bibl-{key}` on the matching `csl-entry`
(first key if a cite has several).
Unknown keys become `span.unresolved-citation` and a page error.

AsciiDoc (Java extensions; no `asciidoctor-bibliography` gem):

- `cite:[key]`, `cite:[key, p. 12]`, `cite:[key1, key2]` — parenthetical
- `cite:key[]`, `cite:key[p. 12]` — same, standard inline-macro form
- `citenp:[key]` — narrative (author in the sentence)
- `bibliography::[]` — list placeholder (otherwise the list is appended)

Markdown (Pandoc citation syntax, scanned after FlexMark; no extra extension):

- `[@key]`, `[@key, p. 12]`, `[@key1; @key2]` — parenthetical
- `@key` — narrative (`me@host.com` is left as an email)
- `[-@key]` — suppress author
- `:::bibliography` — list placeholder
