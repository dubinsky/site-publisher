Generate and publish websites.

For motivation and design choices, see https://dub.podval.org/notes/Publishing/Site%20Publisher.html[Site Publisher].

This file is about how to *use* the generator and the *syntax* of each construct in each markup.

[#usage]
== Usage

The source directory must contain `_site_config.yml`. Pass that directory as the only positional argument:

----
./gradlew run --args="/path/to/source-directory"
----

`./gradlew build` compiles and tests; `./gradlew test` runs tests only.

[#frontmatter]
== Frontmatter

Internal (YAML between `---` lines in the markup file) or external (same basename, `.yaml` / `.yml`). Do not use both.

Set `title` in front matter only when it differs from the file name. Both the file name and the title are used for link resolution.

Useful fields:

- `chunk` / `chunk-depth` — see <<chunking>>
- `bibliography` / `csl` / `lang` — see <<bibliography>>
- `toc-depth`
- `tags`, `categories`, `aliases`
- `header-page`, `icon`, `permalink`, `post`, `date`
- `pdf` - see <<pdf>>

[#page-names]
== Page Names
Jekyll relies on page titles being given explicitly in the front matter
and ignores the file names; I had to use a TODO Obsidian plugin to set the
titles from the file names to communicate them to Jekyll;
as a result, pages where the title is different from the file name
(e.g., `index` pages)
had to be marked with TODO in their front matter to disable this plugin
from setting the front matter title.

My plugin uses both the front matter title and the file name for
link resolution, so I can remove this Obsidian plugin and
redundant front matter titles which are the same as the file name,
and set the title in the front matter only when it is different from the file name.

Obsidian uses file names exclusively and ignores the front matter title;
for link resolution to use front matter titles also,
TODO Obsidian plugin needs to be installed.

[#chunking]
== Chunking

Split a document into per-section HTML pages (any markup, not only AsciiDoc).

----
chunk: true
chunk-depth: 2
----

Chunked TOC shows ancestors plus the current subtree; sibling branches are titles only.

[#tables]
== Tables

Markdown tables via FlexMark Tables Extension (Obsidian supports them natively).

Markdown::
+
[source,markdown]
----
| A | B |
|---|---|
| 1 | 2 |
----

AsciiDoc tables via Asciidoctor.

AsciiDoc::
+
[source,asciidoc]
----
|===
| A | B

| 1 | 2
|===
----

HTML::
+
[source,html]
----
<table>
  <thead><tr><th>A</th><th>B</th></tr></thead>
  <tbody><tr><td>1</td><td>2</td></tr></tbody>
</table>
----

TEI::
+
[source,xml]
----
<table>
  <row role="label"><cell>A</cell><cell>B</cell></row>
  <row><cell>1</cell><cell>2</cell></row>
</table>
----

[#footnotes]
== Footnotes

Hovering a footnote number shows the note; the numbered list is at the end of the (chunk of the) page.

AsciiDoc:: `footnote:[text]` (Asciidoctor).

Markdown:: FlexMark footnotes: `[^id]` in the text and `[^id]: body` for the definition.

[#glossary]
== Glossary

A glossary is a description list marked as such. Term links get hover definitions (print inlines them in parentheses).

AsciiDoc:: `[glossary]` on the description list; term ids from `[[id]]`. Reference a term with `<<id>>`.

Markdown:: PHP Extra definition lists
(https://michelf.ca/projects/php-markdown/extra/#def-list)
via FlexMark
https://github.com/vsch/flexmark-java/wiki/Definition-List-Extension[Definition List Extension].
Mark the list with `{:.glossary}` after it
(Kramdown https://kramdown.gettalong.org/syntax.html#inline-attribute-lists[IAL],
same family as `{:toc}`).
Without that marker the list is not a glossary (no term ids, no tooltips).
The marker also separates adjacent lists.

Term id is the `id` on `<dt>` if present, otherwise the term text with spaces turned into hyphens
(`Alter Rebbe` → `Alter-Rebbe`).
Reference a term with `[[#id]]` or `[text](#id)`.

A lone `:` after a Markdown term is not a reliable empty definition:
FlexMark can take the next term as that definition.
Write a real definition line, or omit the term.

In HTML the list is `class="glossary"`; each term is `class="glossary-item"` with an `id`.

[#bibliography]
== Bibliography

Per document (no site-wide file or style). Front matter:

- `bibliography` — path to a `.bib` file, relative to this source file
- `csl` — CSL style name from the bundled styles (for example `apa`, `ieee`)
- `lang` — CSL locale; falls back to the site `lang`, then `en-US`

Both `bibliography` and `csl` are required. Only works cited on the page appear in the list.
In-text cites become links to `#bibl-{key}` on the matching list entry
(first key if a cite names several). Unknown keys are highlighted and recorded as a page error.

AsciiDoc (no `asciidoctor-bibliography` gem)::

- `cite:[key]`, `cite:[key, p. 12]`, `cite:[key1, key2]` — parenthetical
- `cite:key[]`, `cite:key[p. 12]` — same, standard inline-macro form
- `citenp:[key]` — narrative (author in the sentence)
- `bibliography::[]` — list placeholder (otherwise the list is appended)

Markdown (Pandoc citation syntax; no extra FlexMark extension)::

- `[@key]`, `[@key, p. 12]`, `[@key1; @key2]` — parenthetical
- `@key` — narrative (`me@host.com` is left as an email)
- `[-@key]` — suppress author
- `:::bibliography` — list placeholder
