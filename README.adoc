= Static Site Publisher
:toc:
:toclevels: 4
:toc: preamble
:icons: font

Generate and publish websites.

For motivation and design choices, see https://dub.podval.org/notes/Publishing/Site%20Publisher.html[Site Publisher].

This file is about how to *use* the generator and the *syntax* of each construct in each markup.

[#usage]
== Usage

The source directory must contain `_site_config.yml`. Pass that directory as the only positional argument:

----
./gradlew run --args="/path/to/source-directory"
----

`./gradlew build` compiles and tests; `./gradlew test` runs tests only.


[#summary]
== Summary

This here is a static site generator. It:

- is <<opinionated>>;
- recognizes various <<markup>> languages;
- interprets <<frontmatter>>;
- resolves various <<page-names>>;
- lists <<directories>>;
- supports <<blog-posts>>;
- supports <<chunking>>;
- supports <<pdf>> generation;
- supports <<tables>>;
- supports <<task-lists>>;
- supports <<footnotes>>;
- supports <<glossary>>;
- supports <<bibliography>>;
- supports <<code-blocks>>;
- supports <<callouts>>;
- supports <<admonitions>>;
- supports <<asides>>;
- supports <<quotes>>;
- supports <<strikethrough>>;
- supports <<figures>>;
- supports <<pdf-embed>>;
- supports <<video>>;

[#frontmatter]
== Frontmatter

Internal (YAML between `---` lines in the markup file) or external (same basename, `.yaml` / `.yml`). Do not use both.

Obsidian treats internal YAML as https://help.obsidian.md/properties[Properties]; it stores extra keys but does not interpret this publisher's fields (`chunk`, `bibliography`, `csl`, …).

Set `title` in front matter only when it differs from the file name. Both the file name and the title are used for link resolution.

Useful fields:

- `chunk` / `chunk-depth` — see <<chunking>>
- `bibliography` / `csl` / `lang` — see <<bibliography>>
- `toc-depth`
- `tags`, `categories`, `aliases`
- `header-page`, `icon`, `permalink`, `post`, `date`
- `pdf` - see <<pdf>>

[#page-names]
== Page Names
Jekyll relies on page titles being given explicitly in the front matter
and ignores the file names; I had to use a TODO Obsidian plugin to set the
titles from the file names to communicate them to Jekyll;
as a result, pages where the title is different from the file name
(e.g., `index` pages)
had to be marked with TODO in their front matter to disable this plugin
from setting the front matter title.

My plugin uses both the front matter title and the file name for
link resolution, so I can remove this Obsidian plugin and
redundant front matter titles which are the same as the file name,
and set the title in the front matter only when it is different from the file name.

Obsidian uses file names exclusively and ignores the front matter title;
for link resolution to use front matter titles also,
TODO Obsidian plugin needs to be installed.

[#chunking]
== Chunking

Split a document into per-section HTML pages (any markup, not only AsciiDoc).

----
chunk: true
chunk-depth: 2
----

Chunked TOC shows ancestors plus the current subtree; sibling branches are titles only.

[#tables]
== Tables

Markdown tables via FlexMark Tables Extension (GFM; Obsidian supports them natively).

Markdown::
+
[source,markdown]
----
| A | B |
|---|---|
| 1 | 2 |
----

AsciiDoc tables via Asciidoctor.

AsciiDoc::
+
[source,asciidoc]
----
|===
| A | B

| 1 | 2
|===
----

TEI::
+
[source,xml]
----
<table>
  <row role="label"><cell>A</cell><cell>B</cell></row>
  <row><cell>1</cell><cell>2</cell></row>
</table>
----

HTML::
+
[source,html]
----
<table>
  <thead><tr><th>A</th><th>B</th></tr></thead>
  <tbody><tr><td>1</td><td>2</td></tr></tbody>
</table>
----

[#task-lists]
== Task Lists

Unchecked `[ ]` and checked `[x]` items in a list. The static site shows disabled checkboxes.

Markdown:: GFM / FlexMark Task List Extension (Obsidian supports them natively):
+
[source,markdown]
----
- [ ] open
- [x] done
----

AsciiDoc:: native checklists:
+
[source,asciidoc]
----
* [ ] open
* [x] done
----

HTML:: the IR shape (already a task list; no conversion):
+
[source,html]
----
<ul class="task-list">
  <li class="task-list-item">
    <input type="checkbox" class="task-list-item-checkbox" disabled> open
  </li>
  <li class="task-list-item">
    <input type="checkbox" class="task-list-item-checkbox" disabled checked> done
  </li>
</ul>
----


[#footnotes]
== Footnotes

Hovering a footnote number shows the note; the numbered list is at the end of the (chunk of the) page.

AsciiDoc:: inline note, or a named definition reused with an empty macro:
+
[source,asciidoc]
----
See this footnote:[A note.]
and again footnote:fn[Same note.] later footnote:fn[].
----

Markdown:: FlexMark: use `[^id]` in the text; define `[^id]:` later. Obsidian supports that form natively (https://help.obsidian.md/syntax#Footnotes[Help: Footnotes]). Obsidian also has inline `^[…]` footnotes; this publisher does not.
+
[source,markdown]
----
See this [^note] and again [^note].

[^note]: A note.
----

TEI:: definition and use are the same element at the point of reference (`n` is currently ignored):
+
[source,xml]
----
<p>See this<note place="end">A note.</note>.</p>
----

HTML:: IR stubs (same `footnoteCorrelationId` on the call site and the body):
+
[source,html]
----
<p>See this<span class="footnote-link" footnoteCorrelationId="note"></span>.</p>
<span class="footnote" footnoteCorrelationId="note">A note.</span>
----

[#glossary]
== Glossary

A glossary is a description list marked as such. Term links get hover definitions (print inlines them in parentheses).

AsciiDoc:: `[glossary]` on the description list; term ids from `[[id]]`. Reference a term with `<<id>>`.
+
[source,asciidoc]
----
See <<posuk>>.

[glossary]
[[posuk]]posuk:: verse
----

Markdown:: PHP Extra definition lists
(https://michelf.ca/projects/php-markdown/extra/#def-list)
via FlexMark
https://github.com/vsch/flexmark-java/wiki/Definition-List-Extension[Definition List Extension].
Mark the list with `{:.glossary}` after it
(Kramdown https://kramdown.gettalong.org/syntax.html#inline-attribute-lists[IAL],
same family as `{:toc}`).
Without that marker the list is not a glossary (no term ids, no tooltips).
The marker also separates adjacent lists.

Obsidian does not render PHP Extra definition lists natively
(https://www.markdownguide.org/tools/obsidian/[Markdown Guide: Obsidian]).
Community plugin https://obsidian.md/plugins?id=pandoc-extended-markdown[Pandoc Extended Markdown]
renders Pandoc/PHP Extra `term` / `: definition` lists.
`{:.glossary}` is Kramdown IAL, not Obsidian; it shows as a paragraph in the note.
`+++[[#id]]+++` heading links are native Obsidian.
+
[source,markdown]
----
See [[#posuk]].

posuk
: verse

{:.glossary}
----

Term id is the `id` on `<dt>` if present, otherwise the term text with spaces turned into hyphens
(`Alter Rebbe` → `Alter-Rebbe`).
Reference a term with `[[#id]]` or `[text](#id)`.

A lone `:` after a Markdown term is not a reliable empty definition:
FlexMark can take the next term as that definition.
Write a real definition line, or omit the term.

TEI:: `<list type="gloss">` (or `type="glossary"`) of `<label>` / `<item>`. Term id from `xml:id` on the label, else on the item, else the label text with spaces turned into hyphens. Reference a term with `<ref target="#id">` or `<term ref="#id">`.
+
[source,xml]
----
<p>See <ref target="#posuk">posuk</ref>.</p>
<list type="gloss">
  <label xml:id="posuk">posuk</label>
  <item>verse</item>
</list>
----

HTML:: the IR shape (`class="glossary"`; each term is `class="glossary-item"` with an `id`):
+
[source,html]
----
<p>See <a href="#posuk">posuk</a>.</p>
<div class="glossary">
  <div class="glossary-item" id="posuk">
    <dt>posuk</dt>
    <dd>verse</dd>
  </div>
</div>
----



[#bibliography]
== Bibliography

Per document (no site-wide file or style). Front matter:

- `bibliography` — path to a `.bib` file, relative to this source file (`.bib` files are not copied to the site; un-ignore with `_site_ignore` if you want one published)
- `csl` — CSL style name from the bundled styles (for example `apa`, `ieee`)
- `lang` — CSL locale; falls back to the site `lang`, then `en-US`

Both `bibliography` and `csl` are required. Only works cited on the page appear in the list.
In-text cites become links to `#bibl-{key}` on the matching list entry
(first key if a cite names several). Unknown keys are highlighted and recorded as a page error.

AsciiDoc:: no `asciidoctor-bibliography` gem. Also `cite:key[]` / `cite:key[p. 12]` (standard inline-macro form).
+
[source,asciidoc]
----
- `cite:[knuth79]`, `cite:[knuth79, p. 12]`, `cite:[knuth79, lamport94]` — parenthetical
- `cite:knuth79[]`, `cite:knuth79[p. 12]` — same, standard inline-macro form
- `citenp:[lamport94]` — narrative (author in the sentence)
- `bibliography::[]` — list placeholder (otherwise the list is appended)
----

Markdown:: Pandoc citation syntax (no extra FlexMark extension). `me@host.com` is left as an email.
Obsidian does not format `[@key]` natively.
Community plugin https://obsidian.md/plugins?id=obsidian-pandoc-reference-list[Pandoc Reference List]
recognizes Pandoc citekeys in the note (sidebar; optional inline).
https://obsidian.md/plugins?id=obsidian-citation-plugin[Citations] inserts `[@key]` from a `.bib` file.
+
[source,markdown]
----
- `[@knuth79]`, `[@knuth79, p. 12]`, `[@knuth79; @lamport94]` — parenthetical
- `@knuth79` — narrative (`me@host.com` is left as an email)
- `[-@lamport94]` — suppress author
- `:::bibliography` — list placeholder
See [@knuth79] and [@knuth79, p. 12] and [@knuth79; @lamport94]
----

HTML:: the IR shape:
+
[source,html]
----
<p>See
<span class="citation" data-mode="parenthetical"><span class="citation-item" data-key="knuth79"></span></span>
and
<span class="citation" data-mode="parenthetical"><span class="citation-item" data-key="knuth79" data-locator="p. 12"></span></span>.</p>
<div class="bibliography"></div>
----

TEI:: in-document records, not a `.bib` file and not CSL. `ref` / `ptr` `@target` the `xml:id` of a `bibl` / `biblStruct` in `listBibl`. Empty `ptr` shows `@n` or the id. `cit` with a `quote` is a <<quotes,quote>>, not this.
+
[source,xml]
----
<p>See <ref target="#knuth79">Knuth 1979</ref>
and <ptr target="#lamport94"/>.</p>
<listBibl>
  <bibl xml:id="knuth79">Knuth, Donald E. <title>TeX and Metafont</title>. 1979.</bibl>
  <biblStruct xml:id="lamport94">
    <monogr><author>Lamport, Leslie</author><title>LaTeX</title></monogr>
  </biblStruct>
</listBibl>
----

[#code-blocks]
== Code Blocks

Inline code and fenced blocks. A language class on `<code>` (`language-scala`, …) loads highlight.js; `language-mermaid` loads Mermaid instead.

Markdown:: CommonMark inline `` `code` `` and fenced blocks.
Obsidian supports both natively, including a language identifier
(https://help.obsidian.md/syntax#Code[Help: Code]).
Fenced `+++```mermaid+++` diagrams are native in Obsidian too
(https://help.obsidian.md/syntax#Diagram[Help: Diagram]);
this publisher loads Mermaid for `language-mermaid`.
+
[source,markdown]
----
Use `map` in

```scala
xs.map(f)
```
----

AsciiDoc:: inline `` `code` ``; `[source]` listing (optional language).
+
[source,asciidoc]
------
Use `map` in

[source,scala]
----
xs.map(f)
----
------

TEI:: `<code>` (tagdocs module) with `@lang` for the formal language (not `xml:lang`). A newline in the content is treated as a block and wrapped in `<pre>`. `<eg>` / `<egXML>` are not converted.
+
[source,xml]
----
<p>Use <code lang="scala">map</code> in</p>
<code lang="scala">xs.map(f)
</code>
----

HTML::
+
[source,html]
----
<p>Use <code>map</code> in</p>
<pre><code class="language-scala">xs.map(f)
</code></pre>
----

[#callouts]
== Callouts

Numbered annotations on lines of *verbatim* (listing, literal, or source), plus a list of those annotations. Not a general footnote mechanism.

AsciiDoc:: `<1>` (or `<.>` for automatic numbering) at the end of a line; repeat the numbers in a callout list below. Hide a marker in the raw source behind a line comment (`// <1>`, `# <1>`, `<!--1-->`).
+
[source,asciidoc]
------
[source,ruby]
----
require 'sinatra' <1>
----
<1> Library import
------

HTML:: the IR shape:
+
[source,html]
----
<pre><code>require 'sinatra' <span class="callout" data-value="1">1</span></code></pre>
<ol class="callout-list">
  <li>Library import</li>
</ol>
----

[#admonitions]
== Admonitions

Typed notices (note, tip, warning, …). Not listing <<callouts>> and not asides/sidebars.

Markdown:: Obsidian core https://help.obsidian.md/callouts[callouts] (`> [!type]`; optional title; `+`/`-` to fold). No plugin.
+
[source,markdown]
----
> [!tip] Save time
> Use the shortcut.

> [!faq]- Hidden
> Secret.
----

AsciiDoc:: `NOTE:` / `TIP:` / `IMPORTANT:` / `CAUTION:` / `WARNING:` (paragraph or `[NOTE]====` block; optional `.Title`).
+
[source,asciidoc]
----
NOTE: Auxiliary information.

.Watch out
[WARNING]
====
Multi-paragraph body.
====
----

HTML:: the IR shape (`details` when folded):
+
[source,html]
----
<div class="admonition" data-type="tip">
  <div class="admonition-title">Save time</div>
  <p>Use the shortcut.</p>
</div>
----

[#asides]
== Asides

Untyped auxiliary content next to the main flow. Not an <<admonitions,admonition>>.

AsciiDoc:: `[sidebar]` or a `****` block (optional `.Title`).
+
[source,asciidoc]
----
.Optional Title
****
Auxiliary content.
****
----

Markdown:: no native syntax; Obsidian has none. Write an HTML `+++<aside>+++` block.
+
[source,markdown]
----
<aside>
<p>From Markdown.</p>
</aside>
----

HTML:: `<aside>` (IR adds `class="aside"` if missing); optional title:
+
[source,html]
----
<aside class="aside">
  <div class="aside-title">Optional Title</div>
  <p>Auxiliary content.</p>
</aside>
----

[#quotes]
== Quotes

Block quotations. Not <<admonitions>> (`> [!tip]`) and not <<asides>>.

AsciiDoc:: `[quote]` (or a `____` block); optional `.Title`; attribution and citation title as `[quote, Author, Source]`.
+
[source,asciidoc]
----
.A title
[quote, Jefferson, Papers]
____
A little rebellion now and then is a good thing.
____
----

Markdown:: a CommonMark blockquote (`>`). No attribution syntax (an em-dash line is still quote body). Obsidian `> [!type]` is an <<admonitions,admonition>>, not a quote.
+
[source,markdown]
----
> A Markdown quotation.
----

HTML:: `<blockquote>` (IR adds `class="quote"` if missing); optional title and `<footer>` attribution (`cite` kept as-is):
+
[source,html]
----
<blockquote class="quote">
  <div class="quote-title">A title</div>
  <p>A little rebellion now and then is a good thing.</p>
  <footer class="quote-attribution">— Jefferson<br/><cite>Papers</cite></footer>
</blockquote>
----

TEI:: `<quote>`; `<cit>` groups a quote with `<bibl>` (attribution). A `<bibl>` directly in `<quote>` is attribution too. `<q>` stays inline.
+
[source,xml]
----
<cit>
  <quote>A TEI quotation.</quote>
  <bibl>Jefferson, <title>Papers</title></bibl>
</cit>
----

[#strikethrough]
== Strikethrough

Deleted or superseded text. HTML `<del>` (browser line-through).

Markdown:: GFM `~~text~~` (Obsidian native; FlexMark strikethrough extension).
+
[source,markdown]
----
See ~~struck out~~ here.
----

AsciiDoc:: `[line-through]#text#`.
+
[source,asciidoc]
----
See [line-through]#obsolete phrase# here.
----

TEI:: `<del>`.
+
[source,xml]
----
<p>See <del>TEI struck</del>.</p>
----

HTML:: `<del>` (IR); `<s>` and `span`/`mark` with `class="line-through"` become `<del>`:
+
[source,html]
----
<p>See <del>HTML struck</del>.</p>
----

[#figures]
== Figures

A block image (or other graphic) with an optional caption. Inline images stay `<img>`.

Markdown:: a `![alt](src)` on its own line; optional `"title"` is the caption. Obsidian `![[image]]` embeds stay `<img>` (resolved later).
+
[source,markdown]
----
![A square](pixel.svg "A Markdown figure")
----

AsciiDoc:: block `image::` (optional `.Title`). Inline `image:src[]` is not a figure.
+
[source,asciidoc]
----
.A figure caption
image::pixel.svg[A square]
----

TEI:: `<figure>` with `<graphic url>` and optional `<head>` (caption). `<graphic>` becomes `<img>`.
+
[source,xml]
----
<figure>
  <head>A TEI figure</head>
  <graphic url="pixel.svg"/>
</figure>
----

HTML:: `<figure>` (IR adds `class="figure"` if missing); optional `<figcaption>`:
+
[source,html]
----
<figure class="figure">
  <img src="pixel.svg" alt="A square"/>
  <figcaption class="figure-caption">HTML figure</figcaption>
</figure>
----

[#pdf-embed]
== PDF embeds

A PDF file shown on the page. Not <<pdf,PDF generation>> of a page.

Markdown:: Obsidian `![[file.pdf]]`; optional `#page=N` and `&height=H` (pixels if H is digits). Alias `![[file.pdf|Title]]` is the link label.
+
[source,markdown]
----
![[sample.pdf]]
----

AsciiDoc:: no native block; write the HTML IR (passthrough `++++`).

HTML:: `<object type="application/pdf">` (IR wraps it) or the IR:
+
[source,html]
----
<div class="pdf-embed">
  <object data="sample.pdf" type="application/pdf" aria-label="sample.pdf">
    <a href="sample.pdf">Open PDF: sample.pdf</a>
  </object>
  <p class="pdf-embed-link"><a href="sample.pdf">Open PDF: sample.pdf</a></p>
</div>
----

The sibling link is always visible and is what remains in print (the inner viewer is hidden).

[#video]
== Video

A local video file, or a YouTube/Vimeo player. Local files use HTML `<video>` (like `<audio>`).

Markdown:: Obsidian `![[file.mp4]]` (also `webm`, `ogv`, `m4v`). Alias `![[file.mp4|Title]]` is the fallback link label.
+
[source,markdown]
----
![[clip.mp4]]
----

AsciiDoc:: `video::file.mp4[]` (optional `.Title` becomes a figure caption). YouTube/Vimeo: `video::id[youtube]` / `video::id[vimeo]`.
+
[source,asciidoc]
----
video::clip.mp4[]
----

HTML:: `<video src>` (IR adds `class="video"` and `controls`); a YouTube/Vimeo `<iframe>` gets `class="video-embed"`:
+
[source,html]
----
<video class="video" src="clip.mp4" controls="controls">
  <a href="clip.mp4">Open video: clip.mp4</a>
</video>
----
